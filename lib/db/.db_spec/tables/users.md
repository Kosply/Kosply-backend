# users — implemented

Buyer, seller and staff accounts. A dashboard operator also has an `admins` row; the two id namespaces are disjoint.

## Columns

| Column | Type | Constraint | Notes |
|---|---|---|---|
| `id` | varchar(191) | PK | cuid2, generated by `src/ids.js` |
| `email` | varchar(191) |  | login identifier |
| `username` | varchar(191) |  | shown in the UI |
| `name` | varchar(191) |  |  |
| `passwordHash` | varchar(191) |  | never store plain text |
| `googleId` | varchar(191) null |  | Google `sub`, unique |
| `appleId` | varchar(191) null |  | Apple `sub`, unique |
| `universitas` | varchar(191) |  | required for buyer + seller |
| `programStudi` | varchar(191) |  | required for buyer + seller |
| `bio` | text null |  | seller storefront bio, on the seller profile |
| `photo` | varchar(191) null |  | avatar URL; the client uploads elsewhere and stores the URL |
| `isActive` | tinyint(1) |  | false = login blocked (frozen) |
| `role` | enum |  | account role |
| `createdAt` | datetime(3) |  |  |
| `updatedAt` | datetime(3) |  | maintained by the statement builder |

## Keys

- Primary key: `id`

## Indexes

- `appleId` — unique
- `email` — unique
- `googleId` — unique
- `username` — unique
